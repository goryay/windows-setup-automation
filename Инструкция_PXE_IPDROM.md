# Установка Windows через PXE-сервер IPDROM

**Рабочий документ для сборщика.** Подходит для обеих редакций: Windows 11 Pro и Windows 11 IoT Enterprise LTSC.

---

## 0. Коротко о том, что происходит

Машина ставится «под ключ» по сети. От сборщика требуется:

1. Подключить кабель и две флешки
2. Включить питание и выбрать пункты в меню
3. **Ответить на четыре вопроса про диски**
4. Уйти до следующего дня — полный цикл занимает ~15–16 часов
5. Вернуться и проверить результат по списку

Всё остальное система делает сама: ставит Windows, драйверы, ПО, гоняет стресс-тест, отправляет отчёт на сервер и записывает образ восстановления на флешку.

> **Главное отличие от старой версии инструкции:** раньше после ввода SL можно было уйти сразу. Теперь система задаёт четыре вопроса про диски и ждёт ответа. Пока не ответишь — установка не начнётся. Раздел 3 читать обязательно.

## 1. Что подготовить перед запуском

### 1.1. Две флешки

Нужны **две разные** флешки. Система различает их по объёму, поэтому объёмы важны.

| Флешка | Объём | Для чего | Что на ней окажется |
|---|---|---|---|
| **IpdromREC** | 32–256 ГБ | Образ восстановления | `restore.ffu` (20–50 ГБ) + загрузчик WinPE |
| **IPDROM** | 8–32 ГБ | Документация и ПО | Папки `software`, `drivers`, `Documentation` |

**Обе флешки будут полностью отформатированы.** Всё, что на них есть, пропадёт. Заранее убедись, что на них нет ничего нужного.

Если под рукой только одна флешка — можно пропустить любую из ролей (как именно, написано в разделе 3). Но тогда соответствующий результат не получится: без REC-флешки не будет образа восстановления, без IPDROM-флешки не будет комплекта документации и ПО.

Втыкать обе флешки **до включения питания**, в любые USB-порты.

### 1.2. Сеть

Подключить сетевой кабель **напрямую в LAN-порт материнской платы**. Не через Wi-Fi, не через USB-переходник, не через докстанцию.

Сервер должен быть доступен: `10.0.6.42` (загрузка и файлы), `10.0.6.41` (приём отчётов).

### 1.3. BIOS/UEFI

Зайти в BIOS (обычно `Del` или `F2` при включении) и проверить:

- **Режим загрузки — UEFI**, не Legacy/CSM
- **Network Stack / PXE включён** (обычно в разделе Boot или Advanced → Network Configuration)
- **Загрузка по сети стоит первой** в списке Boot Priority
- **Secure Boot можно оставить включённым** — установка это переживает

Если системный RAID нужен по наряду — его собирают **вручную в RAID BIOS до запуска установки**. Система его не создаёт и не трогает.

## 2. Запуск

### 2.1. Включить питание

Дождаться PXE-меню — текстовое меню на синем фоне. Если вместо него грузится старая система с диска, значит в BIOS не выставлена загрузка по сети первой (см. 1.3).

### 2.2. Главное меню

```
PXE MENU

  Linux installer
  SberOS
  Windows installer      <-- выбрать этот
  iPXE shell
  Reboot system
```

Стрелками встать на **Windows installer**, нажать `Enter`.

### 2.3. Выбор редакции

```
Windows install

  Windows 11             <-- для Pro
  Windows IoT            <-- для IoT Enterprise LTSC
  Windows Server
  <-- back
```

**Какую выбирать — смотреть в наряде на сборку.** Редакция должна совпадать с полем `OS_type` в конфиге SL:

| Что в наряде / конфиге SL | Пункт меню |
|---|---|
| `OS_type = Windows Desktop` | **Windows 11** |
| `OS_type = Windows IoT` | **Windows IoT** |

> Если ошибиться пунктом — установится не та редакция. Ошибка не критичная (машину можно переустановить), но время потеряется. Проверь дважды.

Встать стрелками, нажать `Enter`.

### 2.4. Ввод номера конфига (SL)

```
Enter SL config ID (example: SL111111-002):
Press Enter to use default 'UNKNOWN'
```

Ввести идентификатор из наряда, например `SL111111-002`, и нажать `Enter`.

SL определяет: модель, набор RAID-массивов, какое ПО ставить, какие документы класть на флешку и какое имя получит компьютер. **Ввести пустое значение нельзя** — без SL система не будет знать, что собирать.

Вводить точно как в наряде, с учётом регистра: `SL111111-002`, а не `sl111111-002`.

## 3. Четыре вопроса про диски

После ввода SL машина загрузит WinPE (около минуты) и начнёт задавать вопросы. **Здесь нужно быть внимательным: неверный номер диска сотрёт не те данные.**

Весь текст в консоли — на русском.

### 3.1. Как читать таблицу дисков

Перед каждым вопросом система показывает таблицу:

```
Обнаруженные USB-накопители:

Index  Model                              Size
3      Kingston DataTraveler 3.0          62002160640
4      VendorC ProductCode                31453470720

Размеры в байтах; делите на 1000000000 чтобы получить ГБ.
```

- **Index** — номер диска. Именно его надо вводить в ответ на вопрос
- **Model** — модель, по ней узнаёшь свою флешку
- **Size** — размер в байтах. Разделить на миллиард, чтобы получить гигабайты: `62002160640` → **62 ГБ**, `31453470720` → **31 ГБ**

Номера дисков **не совпадают** с буквами дисков в Windows и могут меняться от машины к машине. Всегда смотри свежую таблицу, а не запоминай номера с прошлого раза.

### 3.2. Вопрос 1 — флешка восстановления

```
IpdromREC = флешка восстановления (restore.ffu).
Индекс RECDISK:
```

Ввести номер **большой флешки (32–256 ГБ)**. В примере выше это `3` (Kingston, 62 ГБ).

Чтобы пропустить — нажать `Enter` без ввода.

### 3.3. Вопрос 2 — флешка с документацией

```
IPDROM = флешка с документацией, драйверами и ПО.
Индекс DOCSDISK:
```

Ввести номер **маленькой флешки (8–32 ГБ)**. В примере это `4` (VendorC, 31 ГБ).

Чтобы пропустить — `Enter`.

> Если по ошибке указать один и тот же диск на обе роли, система это заметит и сама пропустит DOCS, написав `Один диск на ОБЕ роли - DOCS принудительно пропущен`.

### 3.4. Подтверждение форматирования

После каждой выбранной флешки появится предупреждение:

```
*** ВНИМАНИЕ: диск 3 будет ОЧИЩЕН и помечен IpdromREC.
*** ВСЕ данные на этом диске будут ПОТЕРЯНЫ.
Введите YES для подтверждения:
```

**Проверить номер диска в предупреждении.** Если он верный — ввести `YES` заглавными буквами и `Enter`.

Любой другой ответ (`нет`, `y`, пустая строка) отменит форматирование этой флешки, и установка продолжится без неё.

### 3.5. Вопрос 3 — диск для установки Windows

Система заново покажет таблицу, но уже **внутренних дисков**, и напомнит, что уже занято:

```
Обнаруженные внутренние диски (не USB):

Index  Model                                Size
3      KINGSTON SKC3000S512G                512105932800
0      AVAGO MR9361-8i SCSI Disk Device     6000604968960
1      AVAGO MR9361-8i SCSI Disk Device     12001209937920

Уже выбрано:  REC=3  DOCS=4

Для IoT ОБЯЗАТЕЛЬНО выбрать индекс (иначе установка упадёт).
Для Pro введите SKIP чтобы autounattend выбрал цель сам.
Индекс SYSDISK:
```

Ввести номер диска, **на который ставится Windows**. Обычно это внутренний SSD/NVMe — в примере `3` (KINGSTON, 512 ГБ).

**Как не ошибиться:**

- Диски **AVAGO MR9361-8i** — это массивы RAID-контроллера. Это **диски для данных**, Windows на них не ставится
- Ставить нужно на **SSD или NVMe материнской платы** — обычно KINGSTON, Samsung, WD и подобные
- Ориентируйся на размер: системный диск обычно 240–1000 ГБ, массивы данных — единицы и десятки терабайт

| Редакция | Что вводить |
|---|---|
| **IoT** | **Обязательно номер диска.** Без него установка упадёт с ошибкой |
| **Pro** | Можно номер диска, можно `SKIP` |

Дальше — подтверждение, как в 3.4: проверить номер, ввести `YES`.

### 3.6. Вопрос 4 — очистка лишних дисков

```
ОЧИСТКА ЛИШНИХ ДИСКОВ

Стирает таблицы разделов чтобы BIOS не грузил СТАРУЮ ОС.

Обнаруженные внутренние диски (не USB):
[таблица снова]

Уже выбрано:  REC=3  DOCS=4  SYS=3

Индексы через запятую, напр. 2 или 0,2 - Enter/SKIP чтобы пропустить.
Пропустите Диск 0 если это ваш RAID с данными.
SYSDISK/RECDISK/DOCSDISK игнорируются автоматически.
Диски для очистки:
```

**Зачем это нужно.** Если на другом внутреннем диске осталась старая Windows, BIOS может после установки загрузиться в неё вместо новой. Очистка стирает таблицу разделов таких дисков, чтобы этого не случилось.

**Что вводить:**

- Номера дисков **через запятую, без пробелов**: `2` или `0,2`
- Чтобы ничего не чистить — `Enter` или `SKIP`

**На что смотреть:**

- Если **Диск 0 — это RAID-массив с данными заказчика**, его чистить НЕЛЬЗЯ. Не включай его в список
- Диски, выбранные под SYSDISK/RECDISK/DOCSDISK, система пропустит сама, даже если их указать
- На **свежей сборке** обычно чистить нечего — смело жми `Enter`

Дальше — подтверждение: ввести `YES`.

### 3.7. Частые ошибки при вводе

| Ошибка | Что произойдёт | Как правильно |
|---|---|---|
| Ввести `YES` в ответ на «Диски для очистки» | Система попытается найти диск с номером «YES», ничего не найдёт, напишет `Указанный диск недопустим` | В вопросе про диски вводятся **только цифры**. `YES` — это ответ на **следующий** вопрос, про подтверждение |
| Ввести букву диска (`C`, `D`) вместо номера | Диск не будет найден | Вводится **Index** из таблицы, а не буква |
| Ввести номер с прошлого запуска по памяти | Может стереться не тот диск | Всегда сверяйся со **свежей таблицей** на экране |
| Ввести `yes` строчными | Форматирование отменится | Только заглавными: `YES` |
| Указать RAID-массив как SYSDISK | Установка упадёт или встанет не туда | Windows ставится на SSD/NVMe материнской платы, не на AVAGO |

Если ошибся с номером **до** ввода `YES` — просто ответь на подтверждение чем угодно кроме `YES`, шаг отменится.

Если ошибся и уже подтвердил — **не перезагружай машину**, дай доработать до конца и сообщи Илье.

## 4. Дальше всё идёт само

После последнего `YES` вмешательство больше не требуется. Ничего не нажимать, питание не выключать, флешки не вынимать, кабель не трогать.

Порядок этапов и примерное время:

| Этап | Сколько | Что видно на экране |
|---|---|---|
| Загрузка WinPE, подключение к серверу | 1–2 мин | Текстовая консоль |
| Установка Windows | 15–30 мин | Синий экран установки Windows |
| Первый вход, копирование файлов по сети (138 ГБ) | 20–25 мин | Рабочий стол, окно с логом копирования |
| Установка драйверов, Intellect, MegaRAID | 10–25 мин | Окна установщиков |
| **Стресс-тест (AIDA64 + FIO)** | **12 часов** | Окна AIDA64 и консоли FIO под нагрузкой |
| Отправка отчёта, очистка временных файлов | 1–2 мин | Консоль |
| Запись файлов на флешку IPDROM | 5–10 мин | Консоль |
| Подготовка флешки IpdromREC | 2–3 мин | Консоль |
| **Сбор образа восстановления** | **1.5–2.5 часа** | Синий экран WinPE с прогресс-баром DISM |
| Возврат в Windows, защита флешки | 2–3 мин | Рабочий стол |

**Итого около 15–16 часов.** Машину имеет смысл запускать в конце рабочего дня и забирать на следующий.

Дольше всего идёт стресс-тест — 12 часов машина работает под полной нагрузкой на процессор, память и диски. Это штатная длительность, сокращать её нельзя: смысл теста в том, чтобы выявить нестабильность, которая проявляется только на длинной дистанции.

Второй по длительности этап — сбор образа: машина читает весь системный диск целиком.

**Экран в блокировку больше не уходит** — это отключено специально. Если экран вдруг всё же погас и требует пароль, значит что-то пошло не так, см. раздел 6.

За время цикла машина **перезагрузится 3–4 раза**. Это штатно.

## 5. Проверка результата

Цикл завершён, когда машина стоит на рабочем столе Windows под пользователем **IPDROM**. Пройти по списку.

### 5.1. Рабочий стол

- Обои IPDROM (тёмный логотип, телефон 8 800 550-21-85)
- Ярлыки: **Adobe Reader**, **MegaRAID Storage Manager**, **Microsoft Edge**, **Интеллект** или **Интеллект X** (что именно — зависит от SL)
- Три PDF-документа на рабочем столе
- Время и дата в правом нижнем углу — текущие

### 5.2. Имя компьютера

`Win` + `Pause` → раздел **Имя устройства**.

Должно стоять `SLXXXXXX-XXX` — ровно тот SL, который вводил при запуске. Если осталось `DESKTOP-XXXXXXX` — переименование не отработало, нужны логи.

### 5.3. Язык системы

- **IoT** — интерфейс полностью русский
- **Pro** — на текущий момент интерфейс английский, локализация в Pro-образ ещё не добавлена

### 5.4. Флешка с документацией (IPDROM)

Открыть проводник, найти том с меткой **IPDROM**. На нём должны быть три папки:

| Папка | Что внутри |
|---|---|
| `Documentation` | PDF-документы (обычно 3 файла) |
| `software` | 7-Zip, Adobe Reader, драйвер Guardant, дистрибутив Интеллект, ПО MegaRAID |
| `drivers` | Драйверы материнской платы (архив `.7z`), драйвер MegaRAID |

Точный состав зависит от SL: например, при дискретной видеокарте добавится драйвер NVIDIA, при системном RAID — Intel RST.

### 5.5. Флешка восстановления (IpdromREC)

**Важно: в проводнике этой флешки не будет.** После записи образа система прячет её разделы и переводит диск в режим «только чтение», чтобы её нельзя было случайно отформатировать. Это штатное поведение.

Проверять надо по файлу-маркеру. Открыть `Блокнот` и открыть в нём файл:

```
C:\ProgramData\IPDROM\State\IpdromREC_Protected.flag
```

Внутри должно быть примерно такое:

```
Protected at 2026-07-21T14:11:46
Disk number: 5
FriendlyName: Kingston DataTraveler 3.0
FFU size:    28,25 GB
```

**Если файл есть и размер FFU больше 20 ГБ — образ снят успешно.** Система записывает этот файл только после того, как сама убедилась, что `restore.ffu` на месте и достаточного размера.

Если файла нет — образ не снят, нужны логи.

### 5.6. Отчёт на сервере

Архив с отчётами уходит на `10.0.6.41` автоматически. Сборщику ничего отправлять не нужно.

## 6. Если что-то пошло не так

**Три правила:**

1. **Не переустанавливать.** Повторный запуск сотрёт следы проблемы
2. **Ничего не удалять с машины**
3. **Скопировать логи и передать Илье**

Все логи лежат в одной папке:

```
C:\ProgramData\IPDROM\Logs\
```

Скопировать **всю папку целиком** на флешку или сетевую шару и отправить с описанием: на каком этапе встало и что видно на экране. Фото экрана очень помогает.

### 6.1. Типовые ситуации

| Что видно | Что делать |
|---|---|
| В консоли `Указанный диск недопустим` после вопроса про очистку | Введён `YES` вместо номера диска. Не страшно: очистка просто не выполнилась. Продолжай, но запомни на будущее (см. 3.7) |
| Появился экран **выбора языка** или **выбора раздела** Windows Setup | Автоматика не сработала. Выбрать язык, затем раздел `Windows` на том диске, который указывал как SYSDISK, и нажать «Далее». Сообщить Илье — это сигнал о проблеме |
| Синий экран Windows Setup с кодом ошибки | Сфотографировать экран целиком, отправить Илье |
| Окно «требуется .NET Framework 3.5» | Нажать OK и ждать. Если не исчезает — фото и логи |
| Окно AIDA64 «did not close properly» | Нажать OK, скрипт продолжит сам |
| Долго ничего не меняется, **лампочка диска мигает** | Всё в порядке, идёт копирование или сбор образа. Ждать |
| Долго ничего не меняется, **лампочка диска НЕ мигает** | Логи Илье. Не перезагружать без команды |
| Нет файла `IpdromREC_Protected.flag` | Образ не снят. Логи Илье, **флешку не перезаписывать** |
| Имя ПК осталось `DESKTOP-XXXXXXX` | Логи Илье |
| На флешке IPDROM пустые папки или их нет | Логи Илье |
| Нет ярлыков Intellect / Adobe / MegaRAID | Логи Илье |
| Экран заблокирован и просит пароль | Не должно происходить. Логи Илье |

Самостоятельной диагностикой заниматься не нужно — по логам всегда видно, на каком шаге всё встало.

## 7. Восстановление машины из образа

Если готовую машину нужно вернуть к состоянию «только что собрана»:

1. Вставить флешку **IpdromREC** в USB-порт
2. Включить машину и нажимать `F11` или `F12` (зависит от платы), чтобы попасть в **Boot Menu**
3. Выбрать пункт с USB-накопителем — обычно `UEFI: Kingston DataTraveler` или `UEFI: Removable Device`
4. Дождаться загрузки WinPE. Появится экран:

```
==============================================================
 RECOVERY MODE
==============================================================
Found restore.ffu on X:

This will RESTORE the system disk from the recovery image.
ALL DATA on the system disk will be ERASED.
==============================================================

Type R and press Enter to RESTORE (anything else cancels)
```

5. **Чтобы восстановить** — ввести `R` и `Enter`. Дальше система покажет список дисков и спросит, на какой разворачивать образ, и попросит подтверждение
6. **Чтобы отменить** — нажать любую другую клавишу и `Enter`, машина просто перезагрузится

> Появление экрана RECOVERY MODE само по себе означает, что флешка исправна и образ на месте. Этим можно пользоваться как проверкой: загрузиться, увидеть экран, отменить.

По завершении восстановления вынуть флешку и перезагрузиться.

## 8. Шпаргалка

```
1. Две флешки в USB: большая 32-256 ГБ (REC) + маленькая 8-32 ГБ (docs)
2. Кабель в LAN материнской платы
3. Включить питание
4. PXE MENU -> Windows installer
5. Windows 11 (Pro) или Windows IoT -- по наряду
6. Ввести SL, например SL111111-002
7. Индекс RECDISK  -> номер большой флешки  -> YES
8. Индекс DOCSDISK -> номер маленькой флешки -> YES
9. Индекс SYSDISK  -> номер SSD/NVMe (НЕ AVAGO!) -> YES
   (для Pro можно SKIP)
10. Диски для очистки -> Enter (на свежей сборке) -> либо номера через запятую -> YES
11. Уйти до следующего дня (~15-16 часов)
12. Вернуться, проверить по разделу 5
13. Если что-то не так -> скопировать C:\ProgramData\IPDROM\Logs\ -> Илье
```

## Приложение. Отличия Pro и IoT

| | **Windows 11 Pro** | **Windows 11 IoT Enterprise LTSC** |
|---|---|---|
| Пункт меню | `Windows 11` | `Windows IoT` |
| `OS_type` в конфиге SL | `Windows Desktop` | `Windows IoT` |
| Вопрос SYSDISK | можно `SKIP` | **обязательно указать номер** |
| Язык интерфейса | английский | русский |
| Ключ продукта | из образа | зашит в конфигурацию |

Всё остальное — флешки, вопросы про диски, состав ПО, стресс-тест, сбор образа, восстановление — работает одинаково для обеих редакций.
